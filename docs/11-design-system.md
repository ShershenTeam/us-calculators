# 11 · Дизайн-система «Field Manual»

Документ для того, хто малює або верстає сторінки сайту. Описує, **чому сайт виглядає саме так** і **за якими правилами додавати нове**, щоб 143 сторінки лишалися одним цілим, а не збіркою різних макетів.

Код системи — `src/styles/global.css`. Усі візуальні рішення беруться звідти, а не з окремих стилів у компонентах.

---

## 1. Концепція

**Сайт виглядає як американський інженерний довідник, перенесений у телефон.**

Чому саме так:

| Проблема | Відповідь концепції |
|---|---|
| Конкуренти (calculator.net, inchcalculator і подібні) виглядають однаково: сірий сайт, синє посилання, Arial | Теплий папір + чорнило + редакційна антиква дають миттєво впізнаваний вигляд |
| Нам треба довіра: формули з NIST, DOL, IRS | Вигляд друкованого довідника сам по собі читається як «перевірене джерело», а не як стартап-лендинг |
| Головне на сторінці — число | Усі цифри табличні (`tabular-nums`), результат подано як показання приладу, а не як текст |
| Люди відкривають сайт на будмайданчику з телефона | Папір, високий контраст, великі зони натиску, жодних тонких світло-сірих написів |

Три деталі, через які сайт запам'ятовується:

1. **Реєстраційні кутики** (`.sheet`) — тонкі кутові мітки на блоці калькулятора, як на друкарській формі.
2. **Лінійка** (`.ruled-top`) — риски вздовж верхнього краю блока результату й липкого рядка, як на вимірювальній стрічці.
3. **Моношрифтові підписи-індекси** (`.rule-label`) — великі літери врозрядку з тонкою лінійкою до краю, як нумерація розділів у довіднику.

Чого **не** робимо: градієнтів-«хмар», фіолетового на білому, великих декоративних ілюстрацій, скляних карток, тіней-ореолів, анімацій довших за 0,25 с.

## 2. Колір

Усі кольори — змінні CSS в `:root` у форматі **OKLCH**: він дає передбачувану світлість, тому контраст рахується наперед і не «пливе» при зміні відтінку.

| Токен | Світла тема | Роль |
|---|---|---|
| `--bg` | теплий папір | тло сторінки |
| `--surface` | майже білий | картки, поля, шапка меню |
| `--surface-2` | трохи темніший папір | заголовки таблиць, сегменти, степери |
| `--surface-sunken` | «втоплений» папір | підвал, групи полів, рекламний слот |
| `--text` | чорнило з зеленим підтоном | основний текст |
| `--muted` | приглушене чорнило | підписи, пояснення, хлібні крихти |
| `--border` | волосяна лінія | межі карток і полів |
| `--rule` | темніша лінія | лінійки в `.rule-label`, роздільники |
| `--accent` | глибокий зелений | посилання, активний стан, результат |
| `--accent-soft` | світлий зелений | тло блока результату |
| `--accent-line` | середній зелений | риски лінійки, кутики, межа результату |
| `--ochre` | вохра | другий сигнальний колір (акцент у марці, мітки) |
| `--warn` / `--error` | бурштин / цегляний | попередження і помилки введення |
| `--focus` | синій | кільце фокуса (навмисно інший колір, щоб не зливався з акцентом) |

Темна тема — той самий набір із переставленою світлістю, вмикається автоматично за `prefers-color-scheme`. Ручного перемикача немає: на телефоні це системне налаштування.

**Правила.**
- Нового кольору в компоненті не вводимо. Потрібен відтінок — додаємо токен у `global.css`.
- Контраст: текст ≥ 4,5:1, межі елементів керування ≥ 3:1. Перевіряється Lighthouse-перевіркою `accessibility ≥ 95` (зараз 100).
- Колір ніколи не єдиний носій сенсу: помилка — це червона межа **плюс** текст (`docs/06` §7).

## 3. Типографіка

| Роль | Шрифт | Де |
|---|---|---|
| Заголовки `h1`–`h3` | **Newsreader** (змінна антиква) | H1 сторінок, назви секцій |
| Текст, інтерфейс, цифри | **Public Sans** (змінний гротеск Держстандарту США USWDS) | усе інше |
| Формули, індекси, підписи | системний моноширинний | `.rule-label`, кроки обчислення, одиниці |

Чому ці два: Public Sans зроблено для урядових сайтів США — він нейтральний, добре читається дрібним кеглем і має рівні табличні цифри. Newsreader дає сторінці редакційний, «довідковий» тон. Inter свідомо не використовуємо: це шрифт за замовчуванням половини інтернету.

Обидва — самохостовані змінні підмножини `latin`, разом **83 КБ**, лежать у `public/fonts/`, підвантажуються через `<link rel="preload">` у `src/components/Head.astro`. Оновлюються командою `npm run fonts` (виконується автоматично перед кожним `npm run build`).

**Правила.**
- Антиква — тільки заголовки. Кнопка, поле або підпис антиквою — помилка.
- Будь-яке число, яке змінюється під час введення, має клас `.figure` або стоїть у `<td>`: інакше ширина цифр «стрибає».
- Мінімальний кегль тексту в полі — 16 px (`1rem`), інакше iOS Safari збільшує сторінку при фокусі.
- Найдрібніший припустимий кегль — `0.625rem`, і лише для моношрифтових підписів великими літерами.

## 4. Сітка, простір, глибина

- Контейнер сторінки — `max-w-6xl` (72 rem), поля `px-4`.
- Довгий текст — `.prose`, ширина `68ch`. Читабельність важливіша за заповнення екрана.
- Крок відступів — шкала Tailwind (0.25 rem). Між секціями: `mt-8` всередині блока, `mt-12`–`mt-16` між великими секціями.
- Радіуси лише два: `--radius-card` (0.625 rem) для карток, `--radius-field` (0.5 rem) для полів і кнопок.
- Тіні лише три: `--shadow-card` (картка під курсором), `--shadow-raised` (меню), `--shadow-float` (липкий рядок, мегаменю). Тінь «на спокої» у статичних карток відсутня — глибину дає межа, а не розмиття.

Шапка: рядок 64 px (марка + пошук) та рядок категорій 44 px, разом 108 px. Тому в калькуляторах липка колонка результату має `md:top-28`.

## 6. Анатомія сторінки калькулятора

```
хлібні крихти (моно, великі літери)
H1 (антиква, 2–2,75 rem)
один рядок пояснення (muted, ≤ 62 знаки)
┌──────────────────────────────────────────────┐  ← .sheet .ruled-top
│  ПОЛЯ                      │  РЕЗУЛЬТАТ      │     кутики + лінійка
│  (ліва колонка)            │  (липка праворуч)│
└──────────────────────────────────────────────┘
рядок довіри: «Updates as you type · No sign-up · Share the link»
рекламний слот (ніколи вище)
«що порахувати далі»
текст статті (.prose)
FAQ
пов'язані калькулятори
джерела · автор · дата оновлення
```

Між H1 і калькулятором не ставиться нічого — ні картинки, ні реклами (`docs/06` §1). Це правило перевіряє e2e-тест «calculator is above the fold».

## 7. Рух

Одна крива на весь сайт: `--ease-standard: cubic-bezier(0.2, 0, 0, 1)`.

- Переходи стану (колір, межа, тінь): **150–200 мс**.
- Розкриття акордеона, поворот значка: **200 мс**.
- Єдина поява при завантаженні — блок заголовка головної сторінки (`.rise`, 520 мс, затримки 60/140/220 мс). Більше ніде анімацій появи немає: вони заважають людині, яка прийшла по число.
- Анімуються лише `transform` і `opacity`.
- `prefers-reduced-motion: reduce` вимикає все глобально — правило вже в `global.css`, окремо в компонентах його дублювати не треба.

## 8. Доступність

- Кільце фокуса — `2px solid var(--focus)` з відступом 2 px, окремим синім кольором. Ніколи не прибирається.
- Зони натиску ≥ 48×48 px (`min-h-12`), відстань між полями ≥ 8 px.
- Кожне поле має видимий `<label>`; результат оголошується через `aria-live="polite"`.
- Декоративні елементи (кутики, риски, стрілки) намальовані через `::before`/`::after` або мають `aria-hidden`. Але якщо символ видно — він усе одно має контраст ≥ 4,5:1: Lighthouse перевіряє контраст і для `aria-hidden` (через це індекс картки `01` виконано кольором `--muted`, а не `--rule`).
- Темна тема, збільшення системного шрифту і масштабування до 320 px перевіряються e2e-тестами.

| Показник | Межа | Поточно |

Перевірка: `npx @lhci/cli autorun --config=lighthouserc.json`. Налаштування порогів — `lighthouserc.json`, виконується в CI на кожен PR.

## 10. Як додавати нове

1. Візьми наявний компонент. Якщо підходить — не роби новий.
2. Потрібен новий — поклади його в `src/components/ui/`, збери лише з токенів `global.css`.
3. Жодних кольорів, радіусів, тіней і тривалостей «з голови»: усе через змінні.
4. Перевір: `npm run verify` і `npm run test:e2e`, потім Lighthouse за таблицею §9.
5. Якщо правило системи змінилося — спершу онови цей документ, потім код.
