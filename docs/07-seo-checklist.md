# 07 · SEO-чекліст

Чекліст складається з чотирьох частин:

- **A.** Один раз перед запуском сайту.
- **B.** Перед публікацією кожного калькулятора.
- **C.** Посилання ззовні (link building).
- **D.** Щомісячний контроль.

Позначки:
- **[CI]** — перевіряється автоматично при кожному PR (скрипт `seo-lint` + Playwright + Lighthouse). PR з помилкою не зливається.
- **[Ручне]** — робить людина.

---

## A. Перед запуском сайту (один раз)

### A1. Технічна основа
- [ ] HTTPS на всьому сайті, HTTP → HTTPS 301. **[CI]**
- [ ] Один головний хост: `example.com` (без www) → інші варіанти 301. **[CI]**
- [ ] Єдиний формат URL: нижній регістр, дефіси, закінчення `/`. Варіанти без `/` → 301. **[CI]**
- [ ] Справжня 404 (статус 404, а не 200), з пошуком і популярними калькуляторами. **[CI]**
- [ ] `robots.txt`: усе відкрито, закрито `/search/`, посилання на sitemap. **[CI]**
- [ ] XML sitemap окремо для `en` і `es`, `lastmod` = дата реальної зміни контенту (не дата збірки). **[CI]**
- [ ] Жодної сторінки з випадковим `noindex`. Перелік `noindex`-сторінок фіксований: search, 404. **[CI]**
- [ ] `canonical` на кожній сторінці вказує на саму себе без параметрів. **[CI]**
- [ ] `<html lang="en-US">` / `lang="es-US"`. **[CI]**
- [ ] hreflang: `en-US`, `es-US`, `x-default`, взаємні посилання, лише для пар, що існують. **[CI]**
- [ ] Open Graph і Twitter Card на кожній сторінці, OG-картинка генерується автоматично для кожного калькулятора. **[CI]**
- [ ] Favicon, `manifest.webmanifest`, `theme-color`.
- [ ] Заголовки безпеки (HSTS, X-Content-Type-Options, Referrer-Policy). Не впливають на позиції напряму, але це ознака якісного сайту.
- [ ] Калькулятор відрендерений у HTML на сервері: поля, підписи, приклад результату видно без JS. **[CI]**

### A2. Швидкість (Core Web Vitals)
- [ ] LCP < 1,8 с, CLS < 0,05, INP < 200 мс на мобільному профілі. **[CI Lighthouse]**
- [ ] JS на сторінці калькулятора ≤ 50 КБ gzip. **[CI]**
- [ ] Шрифти локально, `font-display: swap`, лише потрібні символи (subset).
- [ ] Зображення AVIF/WebP з `width`/`height`, ліниве завантаження нижче першого екрана. **[CI]**
- [ ] CDN (Cloudflare) з кешем статики на рік і коротким кешем HTML.

### A3. Розмітка schema.org
- [ ] `Organization` (назва, логотип, `sameAs` на соцпрофілі) і `WebSite` на головній.
- [ ] Шаблони: `WebApplication`, `BreadcrumbList`, `FAQPage` (лише для видимого FAQ), `MedicalWebPage` для здоров'я. **[CI: валідація JSON-LD]**

### A4. Довіра (E-E-A-T)
- [ ] About — хто ми, навіщо сайт, як з нами зв'язатись.
- [ ] Methodology — як перевіряємо формули (еталонні приклади з IRS, DOL/FLSA, USDA, виробників матеріалів).
- [ ] Editorial Policy — хто пише, хто рецензує, як часто оновлюємо, як виправляємо помилки.
- [ ] Сторінки авторів з біографією та кваліфікацією. Для Finance і Health — фахівці (CPA/CFP, RD/MD).
- [ ] Contact з реальною поштою, Privacy, Terms, «Do Not Sell or Share» (CCPA), налаштування cookies.
- [ ] Однаковий бренд (назва, лого) на сайті і в соцмережах.

### A5. Сервіси
- [ ] Google Search Console: доменний ресурс, sitemap надіслано.
- [ ] Bing Webmaster Tools + **IndexNow** (Bing, Yandex; індекс Bing використовує й ChatGPT Search).
- [ ] Аналітика з подіями: calculate, copy, share, print, export, «next» кліки.
- [ ] Відстеження позицій ключових запитів — за даними Search Console (звіт Performance по запитах і сторінках).

### A6. Пошук в AI (ChatGPT, Perplexity, AI Overviews)
- [ ] `robots.txt`: відкрити Googlebot, Bingbot, **OAI-SearchBot, PerplexityBot** (вони цитують джерела й дають переходи).
- [ ] Окреме рішення по навчальних ботах (GPTBot, CCBot, Google-Extended): відкрити чи закрити. Це бізнес-вибір, на позиції в Google не впливає.
- [ ] На кожній сторінці на початку одне речення з прямою відповіддю + формула текстом + таблиця прикладів. Такий формат AI найчастіше цитує.

## B. Перед публікацією кожного калькулятора

> Перед цим розділом має бути заповнений бриф сторінки за `09-page-brief-checklist.md` (аналіз запиту, конкурентів, формули). Розділ B перевіряє вже готову сторінку.

### B1. Запит і намір [Ручне, фіксується в issue]
- [ ] Головний запит і його показники взято із зібраних даних (план, `research/`); бриф заповнено Claude за `09-page-brief-checklist.md`.
- [ ] Переглянуто топ-10 Google: який формат перемагає, чого не вистачає лідерам, які фічі мають топ-3.
- [ ] Записано **нашу перевагу** над топ-3: таблиця, графік, друк, експорт, кілька ділянок, правила штатів тощо.
- [ ] Зібрано 5–15 додаткових запитів (варіації, питання з People Also Ask, related searches).
- [ ] Немає канібалізації: жодна інша наша сторінка не цілиться в той самий запит. **[CI: унікальність primary keyword у реєстрі]**

### B2. Мета-теги та URL
- [ ] URL = головний запит: `/time-card-calculator/`. **[CI]**
- [ ] `title` ≤ 60 символів, починається з головного запиту, унікальний. **[CI]** Формат: `Time Card Calculator – Weekly Timesheet with Breaks & Overtime`.
- [ ] `description` 120–155 символів: запит + користь + заклик, унікальний. **[CI]**
- [ ] Один `H1` з головним запитом, унікальний на сайті. **[CI]**
- [ ] Ієрархія заголовків без пропусків (H1 → H2 → H3). **[CI]**

### B3. Калькулятор
- [ ] Видно на першому екрані телефона (375×667). **[CI Playwright]**
- [ ] Стоїть приклад за замовчуванням, результат видно одразу. **[CI]**
- [ ] Блок «How it's calculated» з формулою та підставленими числами.
- [ ] Логіка покрита тестами: ≥ 5 еталонних прикладів, включно з граничними (0, від'ємні, дуже великі, опівніч для часу). **[CI]**
- [ ] Стан калькулятора зберігається в URL, `canonical` без параметрів. **[CI]**
- [ ] Доступність: `label` у кожного поля, `aria-live` для результату, помилки текстом. **[CI axe]**

### B4. Текст сторінки [Ручне + CI на структуру]
- [ ] Перше речення прямо відповідає, що робить калькулятор і для кого.
- [ ] H2 відповідають на реальні питання (PAA, related searches), а не на загальні «What is…».
- [ ] Є розділи: How to use (3–5 кроків) · Formula з прикладом · Examples (таблиця типових значень) · тематичний розділ (правила, нюанси США) · FAQ (4–8). **[CI: обов'язкові розділи]**
- [ ] Обсяг за наміром: 400–700 слів для простих, 1 000–1 800 для складних. Без «води». **[CI: попередження за межами діапазону]**
- [ ] Американські реалії: $, ft/in/yd, lb, °F, формат дат MM/DD/YYYY, 12-годинний час.
- [ ] Текст написаний або відредагований людиною, всі числа в тексті перевірені калькулятором.
- [ ] Факти з джерелами (.gov, .edu, виробники, стандарти). Список `sources` заповнений. **[CI]**
- [ ] Автор, рецензент (обов'язково для YMYL), дата оновлення. **[CI]**
- [ ] Для YMYL — дисклеймер. **[CI]**

### B5. Перелінковка
- [ ] `category`, `related` (4–6), `next` (2–3), `aliases` заповнені в `meta.ts`. **[CI]**
- [ ] У тексті ≥ 3 контекстні посилання на інші калькулятори через `<Calc>`. **[CI]**
- [ ] На нову сторінку ведуть ≥ 3 посилання з інших сторінок (зворотні related + хаб + текст сусідніх сторінок). **[CI: звіт перелінковки]**
- [ ] Анкори описові й різні, без «click here». **[CI: попередження]**
- [ ] Якщо є іспанська пара — hreflang в обидва боки. **[CI]**

### B6. Розмітка й медіа
- [ ] `WebApplication` + `BreadcrumbList` + `FAQPage` проходять валідацію. **[CI]**
- [ ] Схема чи ілюстрація там, де вона допомагає (форма ділянки, приклад табеля): `alt`, стиснена, з розмірами. **[CI]**
- [ ] OG-картинка згенерована. **[CI]**

### B7. Після публікації [Ручне]
- [ ] Сторінка з'явилась у sitemap, IndexNow надіслано (автоматично при деплої).
- [ ] Пріоритетні сторінки — «Request indexing» у Search Console.
- [ ] Посилання на нову сторінку додано з 1–2 сторінок, які вже мають трафік.
- [ ] Через 2–4 тижні: перевірити покази й запити в GSC, дописати текст під запити, за якими сторінка вже показується.

## C. Посилання ззовні (link building)

Без зовнішніх посилань конкурувати важко: навіть новий calcshelf.com має 49 сайтів-донорів. Мета — **10–20 якісних сайтів-донорів на місяць** після запуску.

**Що працює для калькуляторів:**
- [ ] **Вбудовувані віджети.** Кнопка «Embed this calculator» дає код для чужого сайту з видимим брендовим посиланням «Powered by <Бренд>». Цільова аудиторія:
  - ландшафтні та будівельні компанії (gravel, mulch, concrete);
  - HR-блоги (time card, overtime);
  - вчителі (math).

  ⚠️ Правило Google: посилання у віджеті має бути **брендовим і видимим**, не набитим ключовими словами й не прихованим. Інакше це link spam.
- [ ] **Безкоштовні шаблони:** timesheet PDF/Excel, таблиці military time, таблиці конвертації для друку. На такі матеріали охоче посилаються.
- [ ] **Власні дані:**
  - «Overtime rules by state 2026»;
  - «Average cost of concrete / gravel by state»;
  - «Minimum wage → annual salary by state».

  Потім розсилка журналістам і блогерам.
- [ ] **Запити журналістів** (Qwoted, Featured.com, Source of Sources): коментарі з даними → посилання з медіа.
- [ ] **Ресурсні сторінки:** шкільні/університетські добірки математичних інструментів, сторінки «useful tools» у будівельних і HR-блогах.
- [ ] **Згадки бренду без посилань** → лист з проханням додати посилання.
- [ ] **Спільноти** (Reddit, форуми підрядників, Quora) — лише корисні відповіді там, де калькулятор справді розв'язує питання.

**Заборонено:** купівля посилань на біржах, PBN (мережі своїх сайтів), масові каталоги, обмін посиланнями за схемою, ключові анкори в масових розміщеннях. Такі посилання можуть потягнути вниз весь домен.

## D. Щомісячний контроль

| Що | Де | Дія |
|---|---|---|
| Покази/кліки по кластерах | GSC → Performance (фільтр по URL-папках/категоріях) | Розвивати кластери, що ростуть |
| Сторінки з показами, але CTR < 1% | GSC | Переписати title/description |
| Сторінки на позиціях 8–20 | GSC | Дописати контент під запити, додати внутрішні посилання, отримати 1–2 зовнішні |
| Помилки індексації | GSC → Pages | Виправити до наступного місяця |
| Core Web Vitals | GSC → CWV + CI | Усе має бути «Good» |
| Канібалізація (2+ сторінки на один запит) | GSC → Queries → Pages | Об'єднати або розвести наміри |
| Застарілі дані (ставки, закони, мінімальна зарплата, ліміти 401k/IRA) | календар оновлень | Оновити на початку року / при зміні закону, змінити `updated` |
| Слабкі сторінки (0 показів через 6–9 місяців) | GSC | Покращити, об'єднати з сильнішою або прибрати (301) |
| Нові посилання на сайт | GSC → Links | Відстежувати динаміку, дякувати й підтримувати зв'язок з донорами |
| Позиції топ-50 запитів | GSC → Performance | Порівняння місяць до місяця; для топ-сторінок — повтор аналізу конкурентів (`09`, етап 2) |
| Bing | Bing Webmaster | Індексація, позиції |

## Що з цього автоматизуємо в коді

Скрипт `seo-lint` (запускається в CI на кожен PR) перевіряє:
1. довжину й унікальність title, description і H1, ієрархію заголовків;
2. canonical, hreflang (взаємність), `lang`, відсутність випадкового `noindex`;
3. валідність JSON-LD (WebApplication, BreadcrumbList, FAQPage);
4. обов'язкові поля frontmatter: author, reviewer для YMYL, sources, updated, FAQ ≥ 4;
5. перелінковку: related/next заповнені, ≥ 3 контекстних посилання, ≥ 3 вхідних, немає битих і сирітських;
6. зображення: `alt`, `width`, `height`;
7. унікальність головного запиту між сторінками (антиканібалізація);
8. Playwright: калькулятор на першому екрані мобільного, результат з'являється, немає горизонтальної прокрутки;
9. Lighthouse: Performance ≥ 90, Accessibility ≥ 95, SEO = 100, бюджет JS.
